Tag filter — Untagged, Any / All, and mixed sets

The tag filter is a multi-select that does implicit OR. There's no way to surface tasks with no tags, no way to require every selected tag, and no way to express "untagged or tagged with X." This refinement adds those three capabilities with one model — a pinned Untagged pseudo-tag and an Any / All match mode — exposed two ways: in the existing sidebar, and as a standalone popover.

01 · gap

What we can't express today

Three filter intentions the user can describe in one sentence but the current control can't produce.

Intent "Show me my untagged tasks"

Inbox triage: which tasks haven't been categorized yet? Today the picker only lists existing tags. Untagged is not a selectable value.

Intent "Show only tasks tagged work and urgent"

Cross-cutting view. Selecting both today returns the union (work ∪ urgent). There's no toggle to mean intersection.

Intent "Show untagged or work"

"Things I haven't classified yet, plus my work pile." Needs Untagged to be selectable like a tag, plus the OR behavior we already have.

02 · model

One model, two knobs

A single pseudo-tag — Untagged — pinned at the top of the tag list, selectable like any other. A single match-mode toggle: Any (the existing OR) or All (new — AND). Every filter intent above falls out of those two knobs.

Selection Mode Returns
nothing selected — All tasks (no tag filter).
work any Tasks tagged work.
work errand any Tasks tagged work or errand (existing OR behavior).
work urgent all New. Tasks tagged work and urgent.
Untagged any New. Tasks with zero tags.
Untagged work any New. Tasks with zero tags or tagged work (the example case).
Untagged work all Impossible set — a task can't be both untagged and tagged. UI prevents this; see §06.

06 · edges

Edge cases

All + Untagged → guard, don't return empty

The intersection of "has no tags" and "has tag X" is empty by definition. Two reasonable handlings:

  • Auto-flip mode. When the user adds Untagged while all is active, transparently flip the mode to any. Show a small toast: "Switched to Any — All + Untagged would return nothing."
  • Pick one — recommended: when Untagged is selected, the All button is disabled with a tooltip: "Untagged can only combine with Any." Mirrors the chip — when all is active and a user selects Untagged, the other selections clear and mode flips. This avoids a transient empty-state.
EdgeTags with same name as the sentinel

URL encoding uses @untagged as a reserved token (see §07). Tag names containing @ are already disallowed by validation — see internal/tag/validate.go. No collision risk; add a test that confirms.

EdgePalette parity

command-palette.tsx already has a "filter by tag" command per tag. Add one more at the top: Filter by: Untagged. Same path as a real tag — sets tag_filter=any:@untagged.

07 · url shape

One param — tag_filter=

Replaces the repeated tag=foo&tag=bar pattern with a single structured param. The format is <mode>:<name>,<name>,… where mode is any or all and @untagged is the reserved pseudo-tag token. Names are comma-separated and URL-encoded; commas in tag names are escaped server-side per the existing tag-name rules.

No filter

Tag work — Any

/tasks?tag_filter=all:work,urgent
Untagged only
/tasks?tag_filter=any:@untagged
Untagged or work
/tasks?tag_filter=any:@untagged,work

Migration. The server keeps accepting the legacy repeated tag= param for one release as read-only back-compat (treated as any:). The frontend only writes tag_filter=. After one release, remove the legacy path.

Acceptance

  • Selecting Untagged with no tags returns tasks that have zero tags in task_tags.
  • Selecting Untagged + one or more tags in Any mode returns the union of (untagged tasks, tasks tagged with any selected tag).
  • Selecting two or more tags in All mode returns only tasks tagged with every selected tag.
  • The Any/All segmented control persists in the URL via tag_filter and survives reload.
  • Selecting Untagged while All is active flips the mode to Any and clears non-Untagged tags (no transient empty state).
  • The active-filter strip renders joiners (or/and) between tag chips matching the current mode.
  • The command palette gains a Filter by: Untagged entry above the per-tag entries.
  • Legacy URLs with repeated tag= still load correctly (treated as any:) for one release.
  • Shortcut cheatsheet does not change — same controls, no new keys. (Verified in shortcut-cheatsheet.tsx — Tags filter group unaffected.)
09 · open

Resolved in this handoff

  • "Untagged" placement — pinned at top of tag list (one place, not three).
  • Match-mode UX — global Any/All segmented control (not per-chip operators).
  • Untagged + tag intent — union (untagged OR any of the selected tags).
  • Control surface — both: sidebar in-place and a popover. Variant A is the default; Variant B replaces the existing closed-state trigger.
  • URL shape — single structured tag_filter= param.
